>
> - **搜索窗拆成两块玻璃**：搜索框模块与结果模块各自一块 `glassEffect(.regular)` + 圆角 20 +
>   0.5pt 描边，**必须配 `.clipShape`**（否则玻璃往外画 1–3px 暗边）。两块窗可各自拖动。
> - **类型条 + 位置栏取代命令面板**：结果模块顶部十段类型条（全部 / pdf / word / excel / ppt /
>   照片 / 视频 / 音乐 / 压缩包 / 文档），左侧位置栏列出全部位置 / 此 Mac / 每个搜索根。
>   输入 `/` 与 `\` 唤起的命令面板整条链路删除（含设置里的「命令快捷键」卡片）；
>   `quickPick` 只保留「读」——侧边栏仍按用户当年排过的顺序排。
> - **结果区固定 7 行**（`SearchModuleLayout.resultsListHeight` 的函数签名里没有「条数」）：
>   切换筛选时侧边栏不再跳。状态栏不画时高度也留着。
> - **一批先给 200 条 + 「继续搜索」**：`SearchResultWindow` 是「全池 + 当前 limit」，
>   `rows` 是计算属性；每批重新取 `prefix(limit)`，后到的更好结果能挤进来。
> - **图钉钉住 = 快照**：顺序固定为 `currentPinnedResults()` → `present` → `clearSearchSession()`；
>   钉住窗保留当时的类型与位置筛选，**就地重筛**而不是重新搜索；高度开窗时算一次。
> - **模糊搜索**：子序列（≥3 字符、紧凑度 ≥0.34）、容错（≥4 字符、只跟词比编辑距离）、
>   词首缩写单独先扫；`score = 0.72×匹配度 + 0.28×新近度(半衰期 180 天)`，
>   **`score == 0` 表示「这行没评分」**，此时退回 `(rank, name, id)`。
> - **添加来源改成三步翻页**（`SourceWizardFlow`）：选来源 → 连接信息 → 搜索位置；
>   「第 N 步，共 M 步」只由 Core 出，视图写死会被测试抓红。
> - **使用引导重写**：演示从四章扩到五章（输入 / 空格预览 / 筛选 / 钉住 / 继续搜索），
>   并删掉「输入 `/` 选类型、`\` 选位置」这些界面上已经没有的键位。
> - **性能与正确性**：结果时间戳统一走 `DeviceTimestamp`（2000 行 263 ms → <1 ms）；
>   批消息在后台解 JSON；「点在外面收窗」的豁免名单只收**看得见**的窗口
>   （`orderOut` 不清 frame，隐形窗口会留一片禁点区）。

> **v2.1 变更（2026-10-27，1.1.19）**：**两处报障修复 —— 滚轮被高亮拉回、公网站点搜不到**。
>
> - **滚轮不再被拉回**：命令面板的自动定位原来监听 `commandSelection`，而每行
>   `onHover` 会改写 `commandSelection`。滚轮让内容移动 → 指针下的行变了 → 高亮变了 →
>   `scrollTo(anchor: .center)` 把列表拉回原处，净位移 0（键盘操作看不出来，因为那时
>   高亮与滚动本来就是同一个动作）。现改为独立计数 `commandKeyboardNavigationRevision`，
>   只在 `moveCommandSelection`（↑↓ 与数字键）里递增；悬停只写高亮、不触发滚动。
>   判据取**滚动条滑块上沿的 y**：40 次 −40 px 到底即停，反向逐像素回顶，
>   不是「截图看起来动了」；同源码只把监听目标换回 `selection` 的对照组恒在顶部（复现报障）。
> - **OpenList / AList 的坐标系换算**：`/api/fs/search` 返回的 `parent` 是**存储侧**绝对路径
>   （如 `/guest_dir/Book/…`），而授权根记的是**客户端**坐标（`/api/me` 的 `base_path` 之下，
>   如 `/Book`）。不换算就落到授权根之外，自家的 `Scope.narrowTo` 判 `ScopeDenied`，
>   对外表现为「所选目录不在该账号的可搜索范围内」。现在登录后取一次 `base_path` 并缓存
>   （取不到按 `/` 处理），逐条把结果路径换回客户端坐标，越界条目丢弃；整页都越界时明确报
>   「账号基准路径与位置不匹配」，而不是静默退回「搜到 0 条」。
> - **多位置搜索不再串行**：原来「预检根可用 + 搜索」对每个根**串行**发出，N 个根 = 2N 个往返；
>   公网 AList 单次 1–3.5 s，六个位置就要 18 s 以上。改为 4 路并发 + 同一根内预检与搜索并行，
>   结果按 roots 原序合并去重（输出顺序与串行时一致）。实测同站六位置 112 条 3.1–4.0 s。

>
> - **拖动**：起拖点从行首把手扩到**整行**；拖动中的行淡成虚影，落点行高亮；
>   松手用 spring 动画把其余行上下腾位。

> - **右键删除 / 替换**：删除落盘（`hidden` 表），重启不复活；替换是**同位次换人**，

>   构建日志移出安装包（`dart compile` 输出带构建机绝对路径）。

> **v1.9 变更（2026-10-26，1.1.17）**：**位置面板不再按「已连接」过滤候选**。
> 报障是「位置没生效，只能搜本机」——`\` 面板里只剩「全部位置 / 此 Mac」。
> 根因：`SearchCommandCatalog.items` 用 `for source in sources where source.ready` 过滤，
> 而闪寻重启后不会自动连 NAS（刻意设计，避免开机就动钥匙串），于是开机时所有来源
> `ready == false`，用户配好的 NAS 在面板里集体消失。设计上的错在于把「位置」当成
> 「此刻在线的机器」：位置是**用户配过的地方**，配过就该能选。
> 现改为列出所有 `enabled` 来源的全部搜索根，未连上的那条副标题写「· 未连接」；
> `applySearchTarget` 选中未就绪来源时当场发起连接（`interactiveOTP: true`，
> 设备要动态码就地弹框），连上后 `quietConnectSteps` 成功路径补一次 `changedQuery()`
> 自动重搜。顺带把 Provider 字典的键统一为 `config.id`（原用 `config.sourceID` 查，
> id 含非法字符时永远查不到，副标题会恒显示「未连接」）。
> 同版还包括：`\`/`/` 两个命令面板与数字键直选（1.1.15/1.1.16）、
> 位置限定**下推到设备侧**（群晖 `startSearch` / 品牌逐根各发一次，检索时间真实下降）、
> 空格预览（↓ 选中后空格开/关，不污染搜索词）、OTP 两处（点一次就弹、码错在框里说）、
> 授权返回后恢复窗口与草稿、OpenList 转正（TOTP + 修「只能搜到文件夹」）。

## 一、产品形态

闪寻是一个 macOS 菜单栏（`LSUIElement=true`，不进程序坞）文件搜索工具，做三件事：

1. **本地搜索** —— 走 Spotlight（`NSMetadataQuery`）或指定文件夹递归。
2. **应用搜索** —— 扫 `/Applications`、`/System/Applications`、`~/Applications` 的顶层 `.app`（1.0.1 新增）。
3. **网络存储搜索** —— 不经系统挂载，直接与 NAS 通信取回结果；支持群晖 DSM、WebDAV，实验线含飞牛 fnOS。

交互主线：全局快捷键唤起浮窗 → 输入即搜 → 结果列表键盘导航 → Return 打开 / Space 快速查看 / ⌘Return 在访达中显示。

```
└── tools/                      探针与开发期工具（DevTools/ 下是 CLI 与 smoke，非产品）
```

### 分层规则

| 层 | 职责 | 硬约束 |
| --- | --- | --- |
| `FlashFind2App` | SwiftUI 视图、窗口、控制器 | **不可单元测试**（executableTarget，AppModel 无法实例化）；改动靠 build + 人工点验 + 扫源码结构测试 |
| `FlashFindCore` | 搜索协调、Provider、连接管理、错误契约、文案、外观与字号 | 所有可测逻辑必须下沉到这一层 |
| `MyNASCore` | NAS 协议实现（DSM / WebDAV / fnOS） | 仅 Dart 标准库；协议细节不外泄给 Swift |
| `CSQLite` | 本地索引读写 | — |

**为什么 App 层不可测**：`FlashFind2App` 是 executableTarget，SwiftPM 无法把它的 `@MainActor` 类型装进测试宿主。所以任何「能被测试锁住」的判断（按钮该显示什么、状态该怎么变）都必须做成 Core 里的纯函数或值类型，App 层只做调用与渲染。

### 跨进程协议

- Swift 侧 `MyNASProcessBridge` 以**空参数**启动 `mynas-core`，凭据**只经 stdin 管道**传入，不进命令行、不进环境变量、不落盘到子进程。
- 消息是 NDJSON 信封，`fields` 平铺在信封顶层。
- **DSM 的 taskid 永不进 Swift** —— 协议细节被 Dart 侧完全吸收。
- 核心有**代次（processGeneration）**：起/退各 +1；`terminationHandler` 必须校验进程身份，防止迟到回调作用于已换代的进程。

## 四、搜索链路

```
用户输入
  → AppModel.changedQuery()（含防抖；同时关掉首搜键位提示）
  → SearchCoordinator
      ├── LocalSearchProvider
      │     ├── SpotlightProvider（NSMetadataQuery）
      │     └── 指定文件夹递归
      ├── AppSearchProvider（1.0.1 新增）
      │     └── AppCatalog（系统标准目录，不递归，limit 20）
      └── NASSearchProvider（每个来源一个实例，由 NASConnectionManager 唯一持有）
            └── mynas-core
  → 结果合并 → 排序 → 视图
```

### 关键契约

- **就绪判据是拿到 `total`**，不是收到 `finished`。分页游标按 `rawCount` 推进。
- **行级解析失败不致命**：`unparsedCount` 如实上报，不中断整批结果。
- `truncated` / `limitedTraversal` **不是失败**，是如实告知结果被截断。
- `deviceBusy` 计入 failures 刹车，但文案必须说「设备暂时没有给出结果」，不能报成错误。
- **结果上限漏发末批**属已知未修（见第九节 R10）。

### 应用搜索（1.0.1 新增）

- **只扫顶层 `.app`**：递归会把各 App 的 `Helper.app`、`Contents/` 内部的辅助程序翻出来，扫描结果不可用。
- 三个目录：`/Applications`、`/System/Applications`、`~/Applications`；读不到的目录**跳过不抛错**。
- 排序沿用本地文件搜索的 rank 约定：**整名 0 > 前缀 1 > 包含 2**，同 rank 短名优先，再按字母序。
- 大小写与变音符号不敏感（折叠后比较）。
- 应用来源**跟随「本机」作用域**，但**不受「指定文件夹」限制**——用户搜 app 时不该被文件夹范围挡住。
- 结果行显示真实 app 图标（`NSWorkspace.icon(forFile:)`），不是通用文件图标。
- 同一查询内同步跑完，`cancel(queryID:)` 是空操作（没有可取消的中间态）。
- 实机抽查（本机 109 个应用）：`safari`→Safari(0)、`qq`→QQ(0)/QQMusic(1)/QQPlayerMac(1)、
  `pdf`→PDF Expert(1)、`x`→Xcode(1)/Xmind(1)/Codex++(2)/Firefox(2)/Foxmail(2)。

## 五、网络存储架构

### 5.1 来源模型

一个「来源」= 一台 NAS 上的一个搜索位置。`NASSourceConfig` 是配置，运行时实例是 `NASConnection`。

- **Provider 的唯一持有者是 `NASConnectionManager`**：已登录实例走 `install(_:)` 装进管理器，禁止在视图层另写一份字典。配置真变时必须换实例。
- 同 `sourceID` 交接（重连）**不发 disconnect**。

### 5.2 发现与连接

| 环节 | 实现 |
| --- | --- |
| 局域网发现 | Bonjour 浏览 7 类服务（`_smb` / `_webdav` / `_afpovertcp` / `_synology-dsm` 进候选，`_device-info` / `_airplay` / `_ipp` **只判类型**）+ `NWConnection` 并发 TCP 探测；`DeviceClassifier` 判设备类型，`deduplicateByHost` 同主机去重 |
| 地址解析 | 手动输入兼容 `10.20.30.96` / `10.20.30.96:5001` / `https://10.20.30.96:5001` |
| 品牌判定 | **自动识别优先**；引导页第一步不选品牌，失败才给「高级选项」 |
| 断线重连 | `NASAutoReconnect`；判定走 Core 的 `ReconnectEntryState`，有已存密码则静默重连 |
| 断开闸门 | `NASConnection` 有 `sessionClosed` 闸门：迟到的结果与自动重连**不能复活已断开来源** |

### 5.3 SMB 定位

- 一律走 `SMBPath.RelativePath.relative(_:under:)`，**禁止手写 `dropFirst`**。
- **不自动弹访达连接框**：`performMount` 预检 + `manualConnectURL`，全 App 唯一弹框入口。
- 只读，不修改远端。

### 5.4 证书与信任

- `source_trust.dart` + `trust_paths.dart` 管来源信任；`source_pinned_transport.dart` 做证书 pin 校验。
- 群晖自签名场景：pin 不匹配但**系统证书链可信**时放行 —— 这是预期行为，不是故障。
- 证书异常对用户只显示「无法验证…的身份」+「▸ 证书详细信息」，不暴露技术细节。

### 5.5 错误文案

三条失败文案**都住在 Core**，同一 kind 不得有两种说法：

| 出处 | 用途 |
| --- | --- |
| `NASSearchFailureText` | 搜索失败 |
| `OpenFailureText` | 打开/定位失败 |
| `ConnectionFailureText` | 连接失败 |

| 数据 | 位置 | 权限 | 说明 |
| --- | --- | --- | --- |
| 用户偏好 | `defaults` 域 `com.flashfind.v2` | — | 快捷键、本地搜索模式、`ff2.nasSources.v1`、引导完成标记、**`ff2.appearance.v1`（外观三选一，1.0.1 新增）** |
| NAS 凭据 | 系统钥匙串，`service=com.flashfind.v2.credentials` | ACL 由系统管 | **1.1.5 起全部设备合并成一条**（`account=vault`，内容是 `{"v":1,"entries":{…}}`）。此前是「一台设备一条」。ad-hoc 签名下每换一个版本需重新授权一次 |
| 旧明文凭据 | `~/Library/Application Support/FlashFind2/credentials.json` | 0700 / 0600 | 只作**迁移来源**；搬进钥匙串且读回确认后才逐条删除，搬完自行消失 |
| 本地索引 | CSQLite（FTS5） | — | `IndexDatabase.swift` |
| 凭据变更审计 | `nas-search-events.jsonl` | — | 事件 `credentialMutation`，只记操作/来源/剩余条数/原因，**不记密码** |

### 引导状态

- Key：`ff2.onboarding.completed.v1`、`ff2.onboarding.lastStep.v1`、`ff2.searchHints.shown.v1`
- **进度不存「第几页」**，由真实配置推导（`OnboardingState.make(...)`）：`shortcutConfigured` / `fullDiskAccessGranted` / `localSearchConfigured` / `networkSourceConfigured`。
- 「重跑引导」只清 `completed` 与 `lastStep` 两个 key，**绝不动任何配置**。

### 外观与字号（1.0.1 新增）

| 项 | 实现 | 约束 |
| --- | --- | --- |
| 外观三态 | Core `AppearanceChoice`（system / light / dark） | 默认跟随系统；存的值认不出时**退回系统**，不猜 |
| 应用到窗口 | App `AppearanceController` → `NSApp.appearance` | `nil`=跟随系统（**交回决定权，不是硬套浅色**）、`.aqua`=浅色、`.darkAqua`=深色 |
| 应用时机 | `applicationDidFinishLaunching` 开头 | **必须早于任何窗口出现**，否则首帧会闪一下错误外观 |
| 持久化 | `ff2.appearance.v1`，与其它设置同源（`ClientPreferences`） | 不另开存储 |
| 标题字号 | Core `SettingsTypography`（**17** / 16 / 13 / 11） | 四级严格递减、相邻差 ≥1pt、`sectionHeader ≥ body+3`（16≥13+3）、`caption ≤12`、`pageTitle == 17`，由测试锁 |
| 外观行排版 | App `SettingsView`：`LabeledContent("外观")` + `Picker(...).pickerStyle(.segmented)` | 参照 macOS 系统设置「外观与语言」页（用户 2026-10-14 截图）：左标签 + 右侧分段选择器**一行排布**；结构测试锁定不许退回竖排单选组（`radioGroup`） |

**为什么外观要下沉 Core**：判定「存的值是什么、认不认得出、默认是什么」是纯逻辑，必须能被测试锁住；App 层只负责 `NSApp.appearance` 这一次赋值。与其它 controller 一样，`AppearanceController` 搬出 AppModel 后**必须桥接 `objectWillChange.sink`**，否则数据变了界面不刷新。

### 已知坑

- `UserDefaults.bool(forKey:)` **分不清「没设过」与「显式 false」**（R01）—— 需要区分时必须用 `object(forKey:)`。
- 字典型 `@Published` **不观察 value 的内部状态变化**：凡「实例内部翻转的布尔」驱动界面，必须显式重发或让行视图直接观察实例（BUG-NAS-RECONNECT-02 的根因）。

## 七、错误契约

单一出处链：

```
MyNASCore/lib/error_kinds.dart
   → tools 导出脚本 → error_kinds.json
   → Swift FlashFindCore 侧
```

两侧各有测试；Swift 侧同时校验 JSON 与 Dart 源码，防止单边漂移。

`coreFailure` 的 `errorDescription` 返回 kind 本身；**不要用 `localizedDescription` 兜底 `FlashFindError`**。

> 测试输出提示：`AdapterUnavailable` / `TaskNotFound` / `UnknownApiError` / `UnsupportedVersion` 是 Swift 侧尚有、Dart 侧已无的历史遗留 kind，属通知性质，不阻断。

## 十一、AI 接入层（1.1.2）

让支持 MCP 的 AI 客户端用上闪寻的检索能力。**默认关闭**，用户在 设置 ▸ AI 里打开
开关并勾选来源之后才存在对外接口。

### 11.1 进程结构

```
AI 客户端（Claude / Cursor / WorkBuddy …）
        │  stdio（JSON-RPC，MCP 协议）
        ▼
flashfind-mcp   ← 助手，Contents/Helpers/ 下，随 App 分发
        │  unix socket，0600，仅同一登录会话
        ▼
闪寻.app（权威端）─► 搜索协调 → 本机索引 / NAS Provider
```

**为什么是「助手 + socket」而不是把 MCP 直接塞进 App**：AI 客户端拉起的是它自己配置的
一个命令，App 不可能被它「重新启动一份」。所以助手只做协议翻译，真正的授权、来源快照、
搜索与历史全部留在 App 里——**App 关掉就等于接口不存在**，不需要第二套开关。

反向的诱惑是「设置里关了 AI 就别开 socket」，但那样助手拿到的是一个「连不上」的
错误，用户看到的是「AI 客户端坏了」，而不是「你没开这个功能」。所以 socket 常在，
**在协议层回未授权**。

### 11.2 六个 Tool

| Tool | 作用 | 关键点 |
| --- | --- | --- |
| `list_sources` | 列出被授权的来源 | 只回授权范围内的 |
| `search` | 按关键词搜文件名 | 参数只有 `query` / `limit` / `source_ids` |
| `locate` | 「有没有这个文件」 | 模糊匹配 + 排序 |
| `locate_many` | 一次问多个关键词 | 参数是 `queries` + `per_query_limit` |
| `get_metadata` | 按 `file_id` 取元数据 | **先判读范围再碰文件系统**（11.4） |
| `recent` | 最近访问过的文件 | 按文件去重后翻页（11.4） |

### 11.3 交出去什么

`file_id` 是**不透明标识**，不是路径：明文路径不出本机，AI 拿到 id，由客户端侧
反查合成路径。回给 AI 的字段是闭集（名称、所在来源、大小、时间、类型等），
**不含文件内容、不含绝对路径**。

### 11.4 三条容易被写错的边界

1. **读范围要跟着用户走**。搜索本身按 `LocalSearchMode` 分流，但 `get_metadata` 走的是
   另一条链（`MetadataExecutor → snapshot.execution → PathMetadataProviding`），
   那条链上原本只判「来源是否授权」。文件夹模式下，**范围外的旧 `file_id` 仍能问出
   元数据**。现由 `LocalReadScope` 在碰文件系统之前拦：比前缀必须带路径分隔符
   （`工作` 不能放行 `工作备份`）、先 `standardizedFileURL` + `resolvingSymlinksInPath`
   （软链能绕过字符串前缀）、空文件夹列表即空范围。范围外统一回 `not_found`——
   **不给「越权」专用的拒绝码**，因为拒绝本身就是信息泄露。
2. **超时要分首帧与中途**。权威端的语义是「整次操作跑完才回一帧」，用「读空闲超时」
   去压首帧，会把「还在算」误判成「半死进程」——冷态 `locate` 实测要 5 秒以上，
   于是每个会话的第一次调用必失败。正确做法是首帧等满整段预算、中途两块之间才用
   空闲超时，且两者都不越过总预算（否则分段慢速发送能把一次请求拖成任意长）。
   注意**服务端等请求是相反的**：连上却不说话就该掐。
3. **`recent` 要先按文件收敛再限量**。`metadata` 事件每次访问都记一条，先按事件限量
   再折叠的话，一个文件被看 20 次就能把别的文件整个挤出窗口，而 `truncated` 还报
   `false`。SQL 里用 `id IN (SELECT MAX(id) … GROUP BY file_id)` 先收敛（不用窗口函数，
   SQLite 3.25 以下也能跑），上层再翻页填满。

### 11.5 并发与存储

- **同一来源一次只跑一个查询**（`SearchScheduler` 按 `source_id` 排队）。跨 owner 是
  **排队**不是拒绝——「另一个调用方正在搜索」那句提示是**不变量告警**，正常不该出现。
- 两个独立的 sqlite：`ai-history.sqlite`（访问历史，90 天 / 2 万条上限，每小时 tick
  守 24 小时闸门做修剪）与 `ai-file-reference.sqlite`（`file_id` 反查表）。
  **清空 AI 历史不删映射表**——否则 Agent 手里已有的 id 会全部失效。
- 所有入口走**一条串行队列**（`queue.sync`），结构测试数着调用点数，新增入口必须
  同步改阈值。
